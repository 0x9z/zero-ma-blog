10 Linux Commands Every IT Professional Must Know

10 Linux Commands Every IT Professional Must Know

If you’re stepping into IT — sysadmin, helpdesk, networking, security, doesn’t matter — Linux will find you eventually. Maybe it’s a server you need to SSH into at 2 AM. Maybe it’s a Docker container that’s misbehaving. Maybe it’s just a coworker saying “can you check the logs on the box real quick.”

I didn’t learn these commands from a course. I learned them because something broke and I had no other choice. Here are the 10 I reach for the most, and why each one actually matters — not just what it does.

  1. ls -lah

Everyone knows ls. Almost nobody uses it right.

-l gives you the long format: permissions, owner, size, modified date. -a shows hidden files (the ones starting with a dot — configs live here). -h makes file sizes human-readable, so you see "4.2M" instead of "4404019".

Run it as three separate flags if you want, but ls -lah should be muscle memory before you touch anything else in a directory you don't recognize.

  1. cd — and pushd/popd

Not glamorous, but cd - takes you back to the previous directory instantly. When you're bouncing between /etc/nginx and /var/log/nginx fixing a config issue, this alone saves you dozens of keystrokes a day.

  1. grep -r “pattern” .

Something is broken and you don’t know which file is the culprit. grep -r searches recursively through every file in a directory for a string. Add -i for case-insensitive, -n to show line numbers, -l to just list matching filenames instead of every match.

The day you grep through /var/log for an error string and find the exact line that explains an outage — that's the day this command becomes permanent.

  1. chmod and chown

Permissions are where Linux either protects you or blocks you, and understanding them is non-negotiable.

chmod 755 script.sh sets read/write/execute for the owner and read/execute for everyone else. chown user:group file changes who owns it. Half of the "permission denied" errors you'll ever see get fixed with one of these two commands — the other half get fixed by realizing you're not using sudo.

  1. systemctl status

Modern Linux runs on systemd, and systemctl is how you talk to it. status tells you if a service is running, when it started, and — critically — the last few log lines if it crashed.

Pair it with systemctl restart and journalctl -u -f (to follow logs live) and you can diagnose most service failures without opening a single file.

  1. df -h and du -sh *

df -h shows disk space per filesystem — the first command you run when something says "no space left on device." du -sh * shows you the size of everything in the current directory, so you can actually find what's eating the space.

Run them back to back and you’ll find the runaway log file or forgotten backup in under a minute.

  1. top or htop

Server feels slow? top (or htop if it's installed — install it, it's better) gives you a live view of CPU, memory, and which processes are responsible. You're looking for the process pinning a core at 100% or eating all your RAM.

This is the command that turns “the server is slow” from a mystery into a five-second diagnosis.

  1. ssh user@host

If you work in IT and you’re not comfortable with ssh, that's the first gap to close. It's how you get a terminal on a remote machine, and everything else on this list becomes useless if you can't reach the box in the first place.

Learn ssh-copy-id next — it sets up key-based login so you stop typing passwords, and start actually being secure.

  1. tail -f /var/log/syslog

tail shows you the end of a file. The -f flag makes it follow the file live, streaming new lines as they're written. This is how you watch a log in real time while you reproduce a bug or trigger the failure again.

Swap the path for whatever log matters — nginx, auth.log, a custom app log — and you’re watching your system think out loud.

  1. history | grep

You know you ran that exact command last week. You don’t remember the flags. history shows your full command history, and piping it into grep lets you search it instead of scrolling forever.

Small command, but it saves you from re-deriving the same one-liner from scratch every time.

Why these 10

None of these are exotic. That’s the point. Every one of them is something you’ll use in your first week on any Linux box, and all ten together cover almost everything a beginner IT professional actually needs: finding files, fixing permissions, checking services, watching resources, reading logs, and getting into the machine in the first place.

I’m building this list the same way I built my subnet calculator and my backup script — by hitting the wall first, then writing down what got me through it. If you’re earlier in the journey than me, start with these ten. You’ll add the next twenty on your own, the same way I did — one broken thing at a time.
